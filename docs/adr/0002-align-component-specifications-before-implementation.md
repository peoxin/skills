# Align Component Specifications Before Implementation

Every Dataset derivation, Model, Benchmark, and Experiment has a named Markdown specification that records its human-readable contract. Its alignment stage requires Matt's `$grill-with-docs`; the skill stops when that dependency is unavailable, writes the specification only after the design frontier is empty and the user confirms the shared understanding, and reopens the interview when implementation reveals a normative change.

The specification has no `draft` or `confirmed` status. Exact machine-consumed fields remain in project-native configuration where the target project needs them, while the Markdown contract, configuration or custom implementation, and checks must agree. The execution entry consumes the already aligned Experiment, prepares its declared environment using project convention, executes its phases, and checks its declared outputs. It does not create a second execution specification or require a second `$grill-with-docs` interview. A user-created Git commit fixes each reusable component; an Experiment control commit fixes `EXPERIMENT.md`, its configuration, custom phase code, and referenced same-repository environment files.
