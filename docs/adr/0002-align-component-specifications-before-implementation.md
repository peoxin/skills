# Align Component Specifications Before Implementation

Every Dataset derivation, Model, Benchmark, and Experiment has a named Markdown specification that records its human-readable contract. Its alignment stage requires Matt's `grill-with-docs` skill; the skill stops when that dependency is unavailable, writes the specification only after the design frontier is empty and the user confirms the shared understanding, and reopens the interview when implementation reveals a normative change.

The specification has no `draft` or `confirmed` status. Exact machine-consumed fields remain in project-native configuration where the target project needs them, while the Markdown contract, configuration or custom implementation, and checks must agree. The execution entry consumes the already aligned Experiment, fixes it and its declared same-repository dependency closure in one user-confirmed control commit immediately before running, prepares its declared environment using project convention, executes the declared phases, and checks the declared outputs. Component skills do not create commits; a user may create ordinary component commits for local history or reuse, but they are not execution prerequisites.
